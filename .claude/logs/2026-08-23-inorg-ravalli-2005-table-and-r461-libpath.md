## Design Decisions
| Decision | Rationale |
|----------|-----------|
| Scoped the chromium exclusion to just the `_ravalli_2005` call via a new param, rather than editing `chem_groups` directly | `chem_groups[[1]]$chems` is shared by the main/robustness/ravalli variants of this table plus `run_inorg_val_table`; editing it globally would've silently changed 3+ other tables the user didn't ask about |
| Hand-edited the `.tex` before the R environment was fixed, then re-verified by running the real script afterward | Coefficients for the 4 remaining chemicals are unaffected by dropping chromium/detect-share (same 4 regressions), so the hand-edit was a safe stopgap; still re-ran to satisfy the project's "never mark done without running the code" rule |
| Prepended the user's existing local per-user R 4.6 library (`.../win-library/4.6`) ahead of `Z:/ek559/RPackages` in `.libPaths()`, rather than reinstalling everything onto Z: | Discovered the user already had a complete, correctly-built R 4.6 library locally; installing/rebuilding the same packages onto the `Z:` network drive was extremely slow (10+ min hangs, likely SMB per-file latency) vs. ~12s locally. Z: kept as fallback for packages only present there (`data.table`, `foreach`, `glmnet`, etc.) |
| Diagnosed apparent R segfaults as a Git-Bash POSIX-path artifact, not a real R bug | `available.packages()`/`gzfile()` crashed only when invoked through the Bash tool (path translation garbles native Windows paths); identical calls via PowerShell worked fine. Switched to PowerShell for all R installs/verification going forward |
